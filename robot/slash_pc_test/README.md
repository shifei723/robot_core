# 轮式腿机器人 Mac 上位机

通过串口实时显示下位机 (`LeggedRobot` 固件) 回传的机器人信息, 并支持一键全量录制。

## 运行

**推荐用 Web 版** (浏览器显示, 渲染稳定, 4 张实时曲线图):

```bash
cd /Users/shifei/Documents/robot/slash_pc_test

./monitor.sh start               # 启动后台服务并自动打开浏览器
./monitor.sh start --no-browser  # 只启动后台服务, 不开浏览器
./monitor.sh stop                # 停止服务 (释放串口)
./monitor.sh restart             # 重启
./monitor.sh status              # 查看状态 / 帧率 / CRC 错误 / 是否在录制
./monitor.sh log                 # 实时日志 (Ctrl+C 退出)
./monitor.sh open                # 打开页面 http://127.0.0.1:8765/
```

也可以前台运行 (Ctrl+C 停止):

```bash
python3 web_monitor.py            # 默认 8765 端口, 自动连串口 + 开浏览器
python3 web_monitor.py --port 9000 --no-browser --no-auto-connect
```

- 仅依赖 **Python 标准库**, 无需 `pip install` 任何包
- 启动后**自动连接** 串口 (优先 `usbmodem` 设备, 波特率默认 `2000000`),
  页面顶部可随时切换串口/波特率、手动连接或断开
- 服务运行时**独占串口**; 要让其他程序 (Arduino 串口监视器、ROS 节点) 访问机器人,
  先 `./monitor.sh stop`

> 旧版 Tk 界面 (`pc_monitor.py`) 在部分 macOS 上会白屏, 已不再推荐使用。

## 录制 (全量录制)

1. 在「全量录制」区输入 **名称** (留空则按 `rec_年月日_时分秒` 自动命名;
   重名会自动加 `_1`、`_2` 后缀)
2. 选择保存目录 (默认 `slash_pc_test/logs/`)
3. 勾选录制内容: `解码CSV` + `原始bin` (默认全选 = 全量录制)
4. 点 **● 开始记录** → 实验 → 点 **■ 结束记录**

每次录制生成 `logs/<名称>/` 目录:

```
logs/<名称>/
├── data.csv     解码后的全量数据 (含时间戳, 58 列)
├── raw.bin      串口原始字节流 (完整留存, 可用 robot_protocol.py 重新解码)
└── meta.json    录制信息 (端口/波特率/帧统计/字段说明)
```

`data.csv` 列说明见 `meta.json` 的 `csv_field_desc`。时间戳两列:
`t_s` (录制起始起的秒数) 和 `wall_time` (墙钟时间)。

## 协议说明

与固件 `LeggedRobot.ino` / `LeggedRobot.h` 及参考代码
`robot_core/robot/wheeled_legged_pkg/src/robot_functions.cpp` 一致:

- 帧格式: `0x7B 0x2D | len:u16 | payload | crc:u16` (小端)
- CRC16: Modbus 风格 (初值 `0xFFFF`, 多项式 `0xA001`), 覆盖除 CRC 字段外全部字节
- 帧类型 (字段偏移已用 clang `static_assert` 依据 `robot_structs.h` 验证):
  - `ROS_body_t` 182B 全量帧: 里程计@4, IMU@20, 电机@60, SBUS@156, 状态@176
  - `ROS_body_t1` 124B 精简帧: 电机@4, SBUS@100
- 同一份数据会以**三种等价形态**出现，每个控制周期只发其中一种，
  因此**帧率 = 主循环 = 100 Hz**（早期文档误记为「每周期两帧、帧率翻倍」）:

  | 形态 | 长度 | 起始字节 | 说明 |
  |------|------|----------|------|
  | 标准帧 | 182B | `7B 2D B6 00` + 载荷 | 常规发送路径 |
  | 变体帧 | 181B | `BD 4B 1B` + 载荷 | 固件第二发送路径的 3 字节魔数 |
  | 缺头帧 | 181B | `2D B6 00` + 载荷 | 标准帧被链路吞掉首字节 `0x7B` 后的形态 |

  三者载荷 / count / CRC 完全一致。解析器用「锚点定位 + CRC 确认」统一处理，
  缺头帧会自动补回 `0x7B` 后参与校验。

## 串口独占与丢帧

**串口是独占的**：`mac_serial.open()` 会设置 `TIOCEXCL`，服务运行期间其他程序
（Arduino 串口监视器、另一个上位机、自己的测试脚本）再打开同一 `cu.*` 设备会直接
报 `Resource busy`。这不是限制，而是必要的——macOS 的 `cu.*` 默认允许多进程同时打开，
而**两个读取器会把字节流撕碎**：双方都出现大量 CRC 错误、丢帧从 13% 飙到 90% 以上
（实测单读 85 Hz / 0 CRC 错，双读 5~57 Hz / 上百 CRC 错）。若看到此类症状，
先用 `./monitor.sh status` 确认没有第二个读取器。

### 丢帧曾被误判为「下位机侧问题」，真实原因是解析器（已修复 2026-10-25）

历史现象：收帧率 84 Hz（标称 100 Hz）、丢帧 15%，而 `crc_errors` 始终为 0。
离线用不依赖状态机的方式把 `raw.bin` 完整重扫后，结论反转：

| 项目 | 真相 |
|------|------|
| 链路实际送来的帧 | 1503 / 1717（两份录制） |
| 恢复帧率 | 99.4 / 99.5 Hz |
| **真实丢帧率** | **0.00%**（count 严格 +1，无一处断裂） |
| 链路真正丢弃的字节 | 115 / 143 字节，仅占 **0.04%**，且每次只丢 1 字节 |

**损失放大链**：链路丢掉的这 1 个字节恰好总是某个标准帧的首字节 `0x7B` → 整条帧流
错位 1 字节 → 旧解析器错位后的重同步是「攒满 181 字节赌一次变体 CRC，赌错就把缓冲区
砍到只剩最后 1 字节」，等于一次丢 180 字节 → 像推土机一样碾过完好帧。平均每个丢字节
吞掉 2 帧，把 0.04% 的字节损失放大成 15% 的帧损失。**被吞的帧从未进入 CRC 校验环节**，
所以 `crc_errors` 一直是 0，问题被彻底掩盖。

**修复**：`FrameParser` 改为「锚点扫描式」——用 `7B 2D B6 00` / `BD 4B 1B` /
`2D B6 00` 三种形态在缓冲区里定位候选起点，再用 CRC16 确认、整帧原子消费，缺头帧自动
补回 `0x7B`。缓冲区始终维持在一帧量级，永远不会跨过任何一个合法帧。
同一份 `raw.bin` 修复前后：

| 录制 | 修复前 | 修复后 | 丢弃字节 |
|------|--------|--------|----------|
| 前向扰动 | 1274 帧 / 84.3 Hz | **1503 帧 / 99.4 Hz** | 41564 → **115**（0.042%） |
| 后向扰动 | 1406 帧 / 81.4 Hz | **1717 帧 / 99.5 Hz** | → **143**（0.046%） |

回归：`python3 robot_protocol.py`（自测含缺头帧用例，并对两份 `raw.bin` 断言零丢帧）。

链路仍会偶发丢字节，因此 `meta.json` 现记录 `frames_headless` / `frames_variant` /
`bytes_dropped` / `bytes_dropped_pct` / `frame_hz`，一眼可判断数据是否健康。
排障命令：`python3 frame_loss_test.py 15`（先 `./monitor.sh stop`）。


## 录制数据丢帧补全 (`fill_gaps.py`)

> 本工具针对**修复前的历史录制**：那时 15% 的帧被解析器吞掉，`data.csv` 为不等间隔
> 采样，绘图直接连线会跨过 10~110 ms 的空档。解析器修复后新录制已接近满帧
> （99.4 Hz、缺帧率 ~0），通常不再需要补全。

串口接收存在约 20% 丢帧（旧解析器导致，非 USB 缓冲溢出），原始 `data.csv` 为不等间隔
采样，绘图直接连线会跨过 10~110 ms 的空档。`fill_gaps.py` 做后处理补全：

```bash
python3 fill_gaps.py 录制数据/前向扰动 录制数据/后向扰动
```

- 1 ms 细网格定位样本（不碰撞、不丢样本）→ 连续空档 ≥ 15 ms 判为丢帧缺口
  → 每个缺口用两侧 0.35 s 内的有效样本做 5 阶局部多项式最小二乘拟合
  → 抽取回 10 ms（100 Hz，与控制周期一致）输出 `data_filled.csv`
- 常量列（SBUS / 状态 / 模式）取众数；`count` 取最近有效值；`wall_time` 由 `t_s` 合成
- `data_filled.csv` 列与原文件一致，末列多一个 `filled` 标记（1 = 该行为拟合值）
- **不修改原始 `data.csv`**（首次使用前请自行备份，已备份至 `录制数据/_原始备份/`）
- 同时输出 `fig_gap_fill_<名>_full.pdf`（全程：原始点 / 拟合段 / 缺口底色）与
  `fig_gap_fill_<名>_zoom.pdf`（最大缺口放大）供核对

拟合精度用「随机遮挡 10% 有效样本 → 补全 → 与真值比较」验证：
俯仰角 RMS 0.07~0.08°（峰峰值的 1.1~1.2%）、轮速 0.006~0.008 m/s（约 1%）、
关节位置约 0.7%；陀螺/加速度以噪声为主，拟合值相当于去噪趋势。
用补全数据重算指标与原始数据一致（峰值俯仰角差 < 0.03°、收敛时间差 < 0.1 s）。


## 常见问题

- **窗口白屏/花屏**: 旧版 Tk 界面的已知问题, 请改用 Web 版 `./monitor.sh start`
- **打不开串口**: 确认机器人已开机、USB 已连接; 若被其他程序 (Arduino IDE
  串口监视器等) 或上一个未停止的上位机服务占用, 请先关闭 / `./monitor.sh stop`
- **端口 8765 被占用**: 换端口 `./monitor.sh` 前先 `PORT=9000 ./monitor.sh start`
- **无数据**: 检查状态栏 RX 频率; 若为 0, 确认波特率是 `2000000`
  (固件 `RosSerial.begin(2000000, SERIAL_8N1, RXD1, TXD1)`)
